Memory, Know Your PLACE:Governing Lifecycle State and Query-Time Eligibility in Persistent-Memory Agents

Chen-Fang Hu1, Hong-Han Shuai2,*, Woan-Shiuan Chien2,*

1Arête Honors Program  ·  2Institute of Electrical and Computer Engineering
National Yang Ming Chiao Tung University, Taiwan

*Corresponding authors

Supplementary PDF Citation

TL;DR

Persistent memory can store the wrong current facts—or expose correctly stored facts that should not affect a particular query. PLACE separates state correctness from influence correctness with a write-side certification mechanism and a read-side authorization mechanism. In a controlled Mem0 evaluation, PLACE achieves 1.000 StateCorrectness, zero measured causal leakage in the state-correct paired comparison, and 0.667 / 0.625 JointSuccess on Qwen2.5-7B / 3B.

Abstract

Persistent memory turns prior interactions into durable agent state, but existing systems provide limited control over whether that state remains valid and whether it should influence a later query. We argue that reliable memory requires governance over both state formation and query-time influence. We introduce PLACE, a factorized governance layer that adds write-side state certification and read-side authorization to a memory backend. A factorial evaluation on Mem0 with Qwen2.5-3B and Qwen2.5-7B isolates the contribution of each mechanism. Results show that write-side governance substantially improves lifecycle state correctness, while read-side governance eliminates measured causal leakage from ineligible memory in the state-correct setting. Their combination achieves the strongest joint performance while preserving query-relevant support. These findings show that reliable persistent memory requires explicit control over both maintained state and query-time information influence.

Key Contributions

  • Two complementary governance requirements. We distinguish whether persistent memory represents the correct current semantic state from whether represented memory is eligible to influence a specific query.
  • Certifying Write-Side State (CSS). A governed transition uses trusted user-level events to update the memory backend and verifies the resulting state through physical readback.
  • Query-Authorized Semantic Closure (QASC). A read-only authorization layer constructs query-eligible, model-visible support from physically represented memory; it does not invent missing facts or rewrite storage.
  • Controlled factorial evaluation. We isolate write-side and read-side effects across two model sizes, six governance families, paired causal worlds, and targeted utility and Closed-Loop diagnostics.

Framework

PLACE is a lightweight governance layer around an existing persistent-memory backend. CSS governs which state should be current and verifies what is actually stored; QASC determines which physically supported facts are authorized for the current query. Both mechanisms operate separately from the answer model.

In the example below, a flight originally scheduled for 9:00 is changed to 11:00. CSS marks 11:00 as current. QASC permits the current time and relevant provenance to reach the answer model, while filtering the superseded 9:00 value from a current-time response.

Evaluation at a Glance

The evaluation crosses two write policies (Native and CSS) with two read policies (Native and QASC), yielding four conditions: Native, CSS, QASC, and PLACE. Primary experiments use trusted event and query semantics so governance can be evaluated independently of automatic semantic interpretation.

Main Findings

Finding 01 · Write-side governance

CSS maintains the correct persistent state across the trajectory

Longitudinal StateCorrectness rises from 0.488 to 1.000 for 7B and from 0.414 to 1.000 for 3B. Because QASC does not write memory, Native and QASC share the Native-produced state, while CSS and PLACE share the CSS-produced state. This factorization is verified at all 105 post-event and 48 pre-query checkpoints.

Finding 02 · Read-side authorization

QASC eliminates measured causal leakage when the stored state is correct

CSS and PLACE are the cleanest read-side contrast: all 48 causal pairs are eligible under both, and the authorized states are reference-correct within each paired-world comparison. Replacing Native reading with QASC reduces LeakageRate from 0.125 to 0.000 at 7B and 0.083 to 0.000 at 3B. This is measured leakage on the tested pairs, not a guarantee that leakage is impossible in other settings.

Finding 03 · Factorial combination

Combining CSS and QASC yields the strongest strict joint performance

PLACE achieves JointSuccess of 0.667 at 7B and 0.625 at 3B, versus 0.417 and 0.354 for CSS alone; QASC alone cannot repair an incorrect Native state. InteractionGain is +0.250 (7B) and +0.271 (3B). These are within-trajectory sensitivity results, not population-level evidence of statistical synergy.

Finding 04 · Targeted diagnostics

Authorization preserves needed support and carries into Closed Loop

Reducing ineligible exposure does not require suppressing all memory. PLACE retains 1.000 NeededSupport on applicable Utility probes (15/15 per scale), while reporting 0.000 ExposureRate. In Closed Loop, prior assistant responses remain in non-authoritative dialogue context; PLACE still maintains state correctness and exposure control, although 3B JointSuccess is lower than in Primary.

Finding 05 · Governance-family robustness

The gains extend across all six governance families

PLACE achieves State@Query F1 = 1.000 and LeakageRate = 0.000 across every family at both scales; each PLACE family has eight eligible causal pairs. JointSuccess is positive in all six families, but not uniform: dependency is the weakest (0.375 at 7B; 0.250 at 3B). This pinpoints remaining downstream difficulty even when state formation and authorization are correct.

Finding 06 · Automatic parsing

Semantic interpretation remains a bottleneck outside the trusted-semantics setting

Primary isolates governance with trusted event and query interpretations. In a separate 24-case diagnostic, automatic parsing substantially reduces support and joint correctness. Event-field F1 is 0.776 / 0.456 and query-field F1 is 0.468 / 0.259 at 7B / 3B; transition agreement is 0.583 / 0.000. These parser limits motivate future end-to-end evaluation and should not be conflated with the controlled Primary results.

Finding 07 · Supplementary cross-checks

Visible support helps, but does not guarantee correct final answers

A separate read-only validation of the frozen Primary responses checks conventional similarity and factual/support use. PLACE yields the highest Token F1 at both scales (0.174 / 0.179) and nearly complete required-support visibility (0.989 / 0.989). Yet Support-to-Answer Recall is only 0.497 / 0.614, indicating that available information is not always fully used in the answer. Conventional metrics also need not rank conditions the same way as strict governance JointSuccess.

Scope and Interpretation

These results establish the behavior of PLACE in a controlled, trusted-semantics evaluation. They do not yet demonstrate a fully automatic end-to-end agent, independence across multiple longitudinal trajectories, or population-level guarantees. StateCorrectness and State@Query F1 are different checkpoint metrics. LeakageRate is measured only on eligible paired worlds; a zero reported value does not imply zero risk in every possible history.

The V32 strict-general paper-facing evaluator directly covers 42 of 48 Primary answer obligations; six legacy queries use frozen compatibility scores to preserve the prespecified denominator. The archived evaluator therefore marks this campaign as not yet fully confirmatory-ready under its full-coverage criterion. Conventional answer-quality and support-use cross-checks were computed separately on the same frozen responses.

For precise metric definitions, eligibility criteria, evaluator limitations, and all supplementary tables, consult the supplementary PDF. The StateGain and InteractionGain intervals in the main paper are within-trajectory sensitivity intervals; the causal-pair leakage intervals use pair-level bootstrap resampling.
